# 指導員 勤務予定（今日の予定アプリ）

**URL：https://akira-1229.github.io/Staff-Schedule/**

<img src="qr.png" alt="今日の勤務予定ページのQRコード" width="200">

（スマホのカメラで読み取ると開きます。GitHub Pages を有効にした後から使えます）

👉 **最初の設定手順は [はじめに_やること.md](はじめに_やること.md) にまとめています**

アプリ（ページ）を開くと、**その日の全職員の勤務予定を自動で表示**します。
予定表と班編成表は、アプリの **⚙（設定）からアップロード**するだけです。スマホでもPCでも同じように使えます。

## できること

- 開くと「今日」の予定を表示（◀ ▶ で前後の日も確認）
  - 各班が出勤か休みか（振休・班休・休校日・休日出勤）、全員定時の日
  - 記事・摘要・フォーク（学科・技能）
  - 出勤の人・休みの人の一覧（**名字だけ**で表示。同じ名字の人は「福井(聡)」のように区別）
- 右上の **カレンダーのボタン** で月の一覧（休校日・休日出勤・振休・班休・定時・フォーク）。◀ ▶ やスワイプで月を切り替え、日付を押すとその日の予定へ
- いちばん下の「元の予定表を見る」で、アップロードした元の表をアプリの中で表示（「← 戻る」で戻る、＋で拡大）
- **画面の色**：⚙ で「スマホに合わせる／白／黒」を選べる
- 予定表・体制表は **PDFでも写真でも** アップロードでき、自動で読み取ります（OCR）
- 読み取った内容は**確認画面で元の表と見比べて直してから確定**するので、毎日の表示は正確です
- 毎朝6:40ごろ、その日の予定を GitHub アプリにプッシュ通知（アプリを閉じていても届く）
- アップロード忘れのお知らせ（メール・GitHub アプリ・画面）
  - **予定表**：今日から見た次月の予定表がまだ無いとき
  - **体制表**：4月になってもその年度の体制表が無いとき（4月中にアップロードする決まり）

## アップロードするもの

| ファイル | いつ | 形式 |
|---|---|---|
| **行事予定表** | 次月分を前月中に（2か月分まとめてでもOK） | PDF または写真 |
| **体制表（班編成）** | 1年に一度、**毎年4月中** | PDF または写真 |

### 流れ
1. ⚙ →「予定表を選ぶ」（または「体制表を選ぶ」）でファイルを選ぶ
2. 自動で読み取り（10秒ほど。初回だけ読み取り用の部品の準備に少し時間がかかります）
3. **確認画面**：日ごと（または人ごと）に、元の表の画像と読み取った文字が並びます。違うところを直す
   - オレンジの日は特に確認が必要な日（班の番号を推定した、など）
   - 体制表では「名字」欄がアプリに表示される名前です
4. 「この内容で確定してアップロード」→ ほかの端末やスマホにも1〜2分で反映
- **アップロードするには「GitHubの鍵」が必要**です（アップロードする人の端末だけ。見るだけの人は不要）

## 表の形について

**行事予定表**（聖徳自動車学園の様式）
- 上に「行事予定表（令和8年11月）」→ 何月の予定表か自動で判断（読めなければ確認画面で選ぶ）
- 列：月日・曜日・記事・摘要・班・振休等・フォーク（11時間・31時間・35時間 × 土日・平日）
- 班・振休等の書き方：**(2)出**＝2班出勤、**(2)休**＝2班振休、**②休**＝2班班休、**定時**＝全員定時
- 曜日が丸囲みの日（日曜・月曜）は休校日。「出」と書かれた班だけ出勤
  （休校日の曜日は `config.js` の `closedWeekdays` で変更できます）

**体制表**（聖徳自動車学園の様式）
- 上に「令和8年度…体制表」→ 年度を自動で判断
- 各班の「新」の行の名前を使います。◎＝責任者、○＝副責任者、列の見出し＝担当

写真で撮るときは、**表全体がまっすぐ・明るく写るように**してください（影や斜めはなるべく避ける）。

## 毎朝の通知（GitHubアプリ）

毎朝6:40ごろ、GitHub がその日の予定を読み取り、「【毎朝のお知らせ】2026年11月の勤務予定」という Issue にコメントします。
`notify-users.txt` に書いた人を @メンションするので、GitHub アプリにプッシュ通知が届きます。

```
@akira-1229 11/6（金） 出勤3人：佐藤花子（日） 鈴木一郎（遅） 高橋美咲（日）
```

- 受け取る人：GitHub アカウントを作り、スマホに GitHub アプリを入れてプッシュ通知と「Direct mentions」をオン
- 通知先の追加：`notify-users.txt` に GitHub ユーザー名を1行ずつ書く
- 出勤者0人の日（休業日）は通知しません（`.github/workflows/daily-notify.yml` の `NOTIFY_ON_CLOSED_DAYS`）
- GitHub の混雑で、数分〜数十分遅れて届くことがあります

## アップロード忘れのお知らせ

毎朝9:10ごろ GitHub が確認し、必要なら「【予定表】2026-12 の予定表がまだアップロードされていません」
「【班編成表】2027年度の班編成表がまだアップロードされていません」というお知らせ（Issue）を作ります。
3日おきに再通知し、アップロードされると自動で閉じます。アプリの画面上部にも黄色い帯で表示されます。

予定表は「○月の予定表が提出されているか」だけで判断し、今日から見た次月の分が無ければ、日付に関係なくお知らせします。

## PCで毎朝自動で開く（任意）

`windows\毎朝自動で開く_登録.bat` を PC に保存してダブルクリックすると、毎日7:00と Windows にサインインしたときに、
ブラウザでこのページが開きます。やめるときは `毎朝自動で開く_解除.bat`。

## ファイル構成（開発者向け）

```
index.html, css/, js/app.js   アプリ本体（今日の予定・設定・確認画面）
js/table-image.js             画像から表の罫線・セルを見つける
js/schedule-image.js          行事予定表の読み取り（OCR）
js/teams-image.js             体制表の読み取り（OCR）
js/day-logic.js               その日の出勤・休みのきまり（画面と毎朝の通知で共通）
js/store.js                   アップロードと登録情報（data/manifest.json）
schedules/  teams/            アップロードされた元のファイル
data/schedules/  data/teams/  確認画面で確定した内容（アプリはこちらを使う）
scripts/                      毎朝の通知・お知らせ（GitHub Actions から実行）
lib/pdfjs/  lib/tesseract/    PDF表示・文字の読み取り（OCR）のライブラリ
tests/                        テスト（画像は架空の内容・名前）
```

```
node tests/logic.test.js         # きまり・読み取り後の整理のテスト
node tests/ocr.test.js           # 架空の表の画像を実際に読み取るテスト（Playwright が必要）
node tests/make-fixtures.js      # 架空の表の画像を作り直す
```

ローカルで確認するときは `python -m http.server` を実行し、`http://localhost:8000/?date=2026-11-06` を開きます。
